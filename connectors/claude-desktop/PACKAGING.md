# Unsigned discovery packaging and security boundary

This product produces an unsigned MCPB ZIP archive with five generated files. It does not implement certificate parsing, signing or signature verification. The old scripts used `mcpb validate` and `mcpb pack`, never `mcpb sign` or `mcpb verify`. Inspection of the official MCPB 2.1.2 packer shows `pack` writes only a ZIP; signing is a separate command. The [official MCPB project](https://github.com/modelcontextprotocol/mcpb) explicitly supports creating the archive directly. [Claude's documentation](https://claude.com/docs/connectors/building/mcpb) describes MCPB as a ZIP with a manifest and local server.

The broad CLI imported its signature module, bringing vulnerable node-forge into the build-tool dependency tree even though this product did not use signatures. Replacing that dependency removes the vulnerable code rather than hiding it from audit or patching cryptography. Signed bundles, certificate-chain processing and arbitrary third-party MCPBs are outside this packer's API. A future signed distribution requires a separately reviewed implementation; it cannot reuse this unsigned writer as a verifier.

The replacement validates against the byte-for-byte official MCPB 0.3 schema ([provenance and hash](vendor/README.md)), with pinned Ajv, ajv-formats and fflate versions in the lockfile. It additionally enforces the existing discovery name, fixed Node entry point, module-only package metadata and absence of credential configuration. It allows only manifest, server entry point, package metadata, privacy notice and runtime third-party notices. Unexpected directories/files, symlinks, malformed/missing artifacts and files above 16 MiB are rejected. Build removes stale generated output after rejecting a linked root. Archive writes use an exclusive temporary file and atomic rename, so an existing output symlink is not followed.

Input is the trusted CI-generated local build tree, not a hostile concurrently modified filesystem. The packer never unpacks untrusted archives. Fixed metadata makes repeated packing of the same bytes deterministic. It preserves the file contents and portable relative entry-point layout, using the same ZIP implementation family as the official CLI. The full `npm audit --audit-level=high` gate still runs over all dependencies before the final archive write. Root buyer/security checks are unchanged.

The archive remains unsigned and has no cryptographically authenticated publisher identity. SHA-256 identifies bytes; it is not a signature. Use a trusted reviewed repository/CI artifact and Claude's install prompt. No organization signed-extension requirement, native UI compatibility or directory approval is claimed. Claude still applies its own installation, trust and policy controls.

Tests cover deterministic archive contents, missing/malformed/oversized artifacts, schema/version errors, alternate commands/args/env/entry points, credential configuration, extra private/signature files and symlink rejection. The existing proxy tests continue to reject paid tools and payment metadata. A clean extracted-archive stdio probe verifies public discovery and the bundled synthetic example without credentials or payments; it does not install an extension in Claude's UI.
